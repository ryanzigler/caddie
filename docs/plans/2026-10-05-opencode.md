# OpenCode support

The user requested implementation of the OpenCode integration discussed in this
thread. Preserve Claude and Codex packaging, share workflow bodies, and translate
host behavior explicitly. Execute inline because installation layout, runtime
registration, and prose paths share one contract; obtain independent final review.

## Tasks

1. Package the shared resources and v2 entrypoint at the repository root for
   OpenCode native Git/npm installation and local configuration paths. Register
   native agents at runtime without generating user configuration files. Explicit-only skills
   remain explicitly selectable skills and commands, omitted from model discovery.
2. Add runtime registration of commands and shared agent bodies, skill invocation policy,
   and before/after tool hooks. Reuse the shared Bash checks through canonical
   payloads; report blocks before execution and suppression feedback after edits.
3. Add the OpenCode host reference and route shared instructions by host. Include
   delegation, custom skill authoring, personal modes, MCP discovery, and review.
   Add project-scoped history indexing and bounded digests using session exports.
4. Add meaningful package, runtime, and history tests. Run the existing Python
   suite and fresh OpenCode smoke/invocation checks. Document installation and
   refresh behavior, dependencies, and any unverified host-specific feature.
